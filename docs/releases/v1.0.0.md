# TaskFlow v1.0.0

First stable portfolio release, completing the sixteen-phase development roadmap.
TaskFlow is a multi-tenant C# backend built with .NET 10, ASP.NET Core, EF Core and
PostgreSQL, with a working Azure deployment pipeline.

## Included

- Workspace membership and Owner/Admin/Member/Viewer permissions; tenant-scoped
  repositories and indistinguishable non-member/missing-workspace responses.
- Projects, task assignment and workflow transitions, soft deletion, filtering,
  deterministic sorting and pagination.
- Author-controlled comments and append-only task activity saved with business changes.
- Short-lived access JWTs, rotating refresh tokens, replay revocation, login lockout
  and per-process rate limits.
- Correlated ProblemDetails and structured logs, liveness/readiness probes, explicit
  proxy trust and optimistic concurrency for task/project writes.
- Non-root API/migration images, separate database migrations, restricted runtime
  grants, GitHub OIDC and Azure deployment by recorded image digest.
- Architecture decisions, a runnable HTTP collection and documented OpenAPI operations.

## Final review changes

- Membership writes now serialize per workspace. Concurrent owner removals or
  demotions cannot both pass the last-owner check; queued requests recheck authority.
  This change requires no database migration.
- Shared build settings enforce compiler/analyzer warnings as errors and audit
  direct and transitive NuGet dependencies, including container builds.
- Three PostgreSQL concurrency regression cases bring the suite to **541 tests**:
  129 Domain, 147 Application and 265 API integration tests.

## Validation and scope

The release review covers authorization, tenant queries, authentication transactions,
business/activity atomicity, concurrency, error handling, proxy configuration,
container/migration boundaries and workflow permissions. See
[the final audit](../FINAL-AUDIT.md) for evidence and limitations.

OpenAPI is Development-only. Rate limits are per process; access tokens remain valid
until expiry after logout. There is no MFA, password recovery, automatic refresh-row
cleanup, client If-Match contract, or comment concurrency token. Project/member lists
are not paginated. There is no frontend, email notification or attachment service.
This portfolio release is not an independent security certification.

## Release versus deployment

The `v1.0.0` tag runs CI and publishes API/migration images with source-SHA tags.
Tag publication does **not** deploy production. Production rollout remains the
explicit **Publish containers** workflow run against `main`; follow
[the Azure runbook](../deployment/azure.md). The previously verified production
release predates this final audit fix, so publishing v1.0.0 alone does not put that
fix on the live API. B1 deployments briefly restart the app, and there is no
automatic database rollback.
